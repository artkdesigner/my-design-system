# MCP — подключения

MCP это разъём между агентом и внешними программами: Figma, браузер, источники данных.

## Figma — подключено

Подключён **официальный Figma Dev Mode MCP Server** — он встроен в десктопное приложение Figma и работает локально.

Конфигурация лежит в `.mcp.json` в корне среды:

```json
{ "mcpServers": { "figma": { "type": "http", "url": "http://127.0.0.1:3845/mcp" } } }
```

Токен не нужен: сервер живёт внутри приложения Figma и использует вашу сессию в нём. Поэтому в конфиге нет секретов и её можно спокойно хранить в репозитории.

**Условия работы:**
- десктопное приложение Figma запущено;
- в нём включён Dev Mode MCP Server (меню Figma → Preferences → Enable Dev Mode MCP Server);
- Claude Code открыт с папкой `My design system` как проектом (`.mcp.json` читается из корня проекта).

Проверка живости сервера из терминала:

```bash
curl -s -X POST http://127.0.0.1:3845/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"probe","version":"1"}}}'
```

В ответе должно быть `"name":"Figma Dev Mode MCP Server"`.

### Что умеет

| Инструмент | Зачем |
|---|---|
| `get_design_context` | основной: код, скриншот и структура выбранного узла |
| `get_variable_defs` | переменные — токены цветов, отступов, типографики |
| `get_screenshot` | картинка узла или текущего выделения |
| `get_metadata` | лёгкая карта слоёв, когда узел большой |
| `get_figjam` | чтение FigJam-досок |

### Как адресовать нужное место в файле

Два способа, оба рабочие:

1. **Выделением.** Выделить фрейм или компонент в десктопном Figma и попросить агента посмотреть на текущее выделение.
2. **Ссылкой.** Скопировать ссылку на слой (правый клик → Copy link to selection). В ней есть ключ файла и `node-id` — по ним агент обращается к конкретному узлу.

## Мост сервер ↔ локальная машина

Claude Code здесь выполняется на сервере (`72.56.97.73`), а Figma Dev Mode MCP слушает `127.0.0.1:3845` на локальном компьютере — с сервера этот порт напрямую не виден. Мост — обратный SSH-туннель: локальный компьютер сам пробрасывает свой порт 3845 на loopback сервера, туда же, куда уже смотрит `.mcp.json`.

На локальном компьютере, в отдельном окне терминала (держать открытым на всё время работы с Figma):

```bash
ssh -R 3845:127.0.0.1:3845 -p 2222 root@72.56.97.73
```

(порт 22 на сервере закрыт файрволом — sshd слушает 2222, не забывать `-p 2222`)

После поднятия туннеля агент проверяет порт на сервере тем же curl-запросом из раздела выше. «Переподключает Figma MCP» здесь не автоматическое — Claude Code читает `.mcp.json` и пробует достучаться до `figma` только при своём старте. Если сессия уже была открыта, когда мост поднялся (порт был недоступен при старте), инструменты `mcp__figma__*` в ней не появятся сами: нужно перезапустить Claude Code (закрыть и открыть заново в папке проекта), и уже новый старт увидит поднятый мост и подключит сервер.

Это временный мост: пока туннель открыт, локальный Dev Mode MCP-сервер (без токена, доступ по факту вашей сессии в Figma) виден процессам на сервере. После работы с иконками/макетами туннель закрывать.

Уточнение к абзацу выше: на практике инструменты `mcp__figma__*` появлялись в уже открытой сессии Claude Code без перезапуска — агент подтягивал их через `ToolSearch` по мере надобности. Если всё же не появляются, перезапуск Claude Code остаётся рабочим способом.

### Диагностика зависшего моста

Симптом: `curl` из раздела выше не отвечает и не рвётся (HTTP 000, таймаут), хотя туннель как будто поднят.

1. Проверить на сервере, слушает ли порт:
   ```bash
   ss -tlnp | grep 3845
   ```
   Если пусто — туннель не поднялся вовсе, проблема на локальной машине (тоннель не запущен или упал).
2. Если порт слушает, но `curl` всё равно виснет — типичная причина: **старая SSH-сессия держит порт**, а новый туннель не смог его перебиндить и висит без реального сервера на другом конце. Найти держателя порта (pid в выводе `ss` выше) среди процессов:
   ```bash
   ps aux | grep sshd
   ```
   и закрыть именно старые/лишние сессии (`kill <pid>`) — осторожно, если это чья-то активная интерактивная сессия, а не просто туннель. После этого поднять туннель заново с локальной машины.
3. Если и это не помогает — само расширение Figma не отвечает: на локальной машине выключить и включить заново Figma → Preferences → Enable Dev Mode MCP Server (это перезапускает сам сервер, не только туннель).
4. Быстрая проверка одной командой — `scripts/check-figma-bridge.sh` (см. ниже).

### Автоматизация: что реально можно, а что нет

Сам туннель нельзя поднять с сервера — команда `ssh -R` запускается с локальной машины, где физически открыт Figma, и сервер не может инициировать это подключение сам. Что можно автоматизировать:

- **Скрипт-диагностика на сервере** — `scripts/check-figma-bridge.sh`: проверяет порт и делает пробный запрос, печатает понятный вердикт и следующий шаг вместо ручного набора `curl`/`ss` команд.
- **Автопереподключение на локальной машине** — вместо голого `ssh -R` использовать `autossh`, который сам поднимает туннель заново при обрыве связи (не помогает, если зависает сам Dev Mode MCP Server внутри Figma — это лечится только тумблером в Preferences):
  ```bash
  autossh -M 0 -o "ServerAliveInterval 15" -o "ServerAliveCountMax 3" -R 3845:127.0.0.1:3845 -p 2222 root@72.56.97.73
  ```
