# Переопределения имён токенов

`scripts/name-overrides.json` — аварийный люк для одной конкретной ситуации:
правило перевода имён (`scripts/lib/naming.mjs`) схлопывает повторяющиеся
слова пути и может свести две РАЗНЫЕ переменные Figma к одному имени CSS.
Если у них разные значения — это не дубль, а настоящая коллизия имён, и
`parseExport` откажется собирать пакет токенов, пока она не разведена.

## Когда пользоваться

Только для этого одного случая — коллизии CSS-имени между двумя переменными
Figma с разными значениями. Файл не предназначен для:

- переименования токенов «для красоты» или удобства;
- обхода проверки «имя непригодно для CSS» — переопределение проходит ту же
  проверку, что и обычный перевод, и падает точно так же, если имя негодное;
- любых других правок соответствия «путь Figma → имя CSS».

## Почему не переименовать в Figma сразу

Переименовать переменную в Figma — правильное и окончательное решение, и
рано или поздно кто-то это сделает. Но конвейер генерации токенов не должен
намертво вставать из-за одной пары имён, пока это не случилось: нужна
отдельная, явная и прослеживаемая лазейка, которая разводит коллизию, не
блокируя остальную работу, и оставляет след в git-истории с объяснением.

## Формат

```json
{
  "Путь/переменной/в_figma": "--итоговое-имя-css-переменной"
}
```

Ключ — точный путь переменной в Figma (поле `name` из выгрузки плагина, как
есть: со слэшами и подчёркиваниями). Значение — готовое имя CSS-переменной
целиком, включая два дефиса в начале.

Переопределённое имя обязано быть пригодным для CSS (та же проверка, что и
для обычных переведённых имён) и участвует в проверке коллизий наравне со
всеми остальными именами — если само переопределение с чем-то столкнётся,
это тоже будет поймано.

Запись, которая не сослалась ни на одну переменную в текущей выгрузке, —
тоже нарушение: значит переменную в Figma уже переименовали или удалили, и
запись здесь пора убрать.

## Каждая запись — долг

Каждая строка в этом файле — расхождение между кодом и макетом Figma,
которое рано или поздно нужно закрыть переименованием в Figma. Не копите
записи «на всякий случай» и не оставляйте их дольше, чем нужно: это ровно
тот мусор, который иначе годами тянется в проекте.

## Текущие записи

- `Input/Input/Input_stepper_padding_hor` → `--input-stepper-slot-padding-hor`.

  Без переопределения эта переменная схлопывается в `--input-stepper-padding-hor`
  и сталкивается с `Input/Stepper/Stepper_padding_hor`, которая схлопывается в
  то же самое имя. У них разные значения (L=8, M=4, S=4 против L=12, M=8,
  S=6) — это два разных токена: отступ вокруг степпера внутри поля ввода и
  отступ внутри самого степпера. Слово «slot» в переопределении отличает
  первый от второго.
