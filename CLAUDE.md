# Спецификация базовой среды дизайнера

Это спецификация, по которой агент разворачивает **базовую** рабочую среду продуктового дизайнера. По команде развернуть — выполнить раздел «Развёртывание». Разворачивать только базу: готовые скиллы, субагентов и процессы не создавать, оставлять пустые каркасы с пояснением.

## Версия

- Архитектура агентов Anthropic, актуальна на июль 2026.
- Модель: Claude Opus 4.8 (`claude-opus-4-8`), вышла 28 мая 2026, текущая старшая.
- Инструмент: Claude Code (десктопное приложение).

## Состав среды

Базовых кирпича несколько. Эта спецификация ставит только фундамент (первые два), остальное добавляется по мере появления реальной потребности.

1. **CLAUDE.md — память проекта.** Файл, который агент читает каждый раз: правила работы, ограничения, договорённости по проекту. Фундамент среды, обычно создаётся командой `/init`.
2. **MCP — подключения.** Разъём к внешним программам: Figma (чтение и сборка макетов), браузер, данные.
3. **Скиллы (`.claude/skills/`).** Папка с инструкцией под конкретную задачу (`SKILL.md`), подтягивается по нужде (прогрессивное раскрытие). В базе не наполняется.
4. **Субагенты (`.claude/agents/`).** Отдельные агенты со своим окном контекста и инструментами; оркестратор раздаёт им куски работы. В базе не создаются.
5. **Тонкая настройка.** Хуки, свои slash-команды, режим плана — на зрелом процессе.

Принцип: минимальный фундамент, наращивание только нужного. База намеренно небольшая.

## Развёртывание

По команде развернуть собрать только базу. Готовые скиллы, субагентов и процессы не создавать. В конце вывести дерево и предложить первую задачу для проверки, что среда живая.

### Шаг 1. Структура
```
.claude/skills/        — пусто; каркас под будущие скиллы
projects/              — рабочие проекты
mcp/SETUP.md           — подключение Figma MCP
README.md              — короткий индекс среды
```
Файл `CLAUDE.md` уже существует (эта спецификация), он дополняется на шаге 3.

### Шаг 2. Каркас скиллов
В `.claude/skills/` создать только `README.md` с пояснением: это место для скиллов — папок с `SKILL.md` под конкретные задачи (ресёрч, сборка экранов, дизайн-система). В базовой среде пусто намеренно, скиллы собираются под задачи отдельно. Готовых скиллов не класть.

### Шаг 3. Память проекта
Дополнить этот файл коротким блоком «Память проекта» (фундамент, держать кратко, в духе `/init`):
- роль и проект: продуктовый дизайнер, рабочая среда;
- договорённости: артефакты в `projects/<имя>/`; цвета и компоненты из дизайн-системы, не прибивать значения руками;
- безопасность: перед необратимым (удаление, публикация) запрашивать подтверждение.
Не раздувать: память проекта это короткий список правил.

### Шаг 4. MCP (`mcp/SETUP.md`)
Записать краткую заметку: для работы с Figma подключается Figma MCP (правка `~/.claude.json`, секция `mcpServers`). Ключи и токены в открытом виде не хранить. Детальную настройку оставить ссылкой, автоматически не выполнять.

### Шаг 5. README и отчёт
Собрать `README.md`: что за среда, что есть сейчас (база), что добавляется дальше (скиллы, субагенты, процесс). Вывести дерево и предложить первую простую задачу для проверки (например: короткий продуктовый ресёрч по идее пользователя; либо подключение Figma и показ файла).

## Правила среды после развёртывания

- Среда базовая. Под повторяющиеся задачи заводятся отдельные скиллы; крупные задачи дробятся на субагентов. В базе этого нет, добавляется по потребности.
- Артефакты — в `projects/<имя-проекта>/`.
- Дизайн-задачи вести через дизайн-систему: компоненты и токены, не значения руками.
- Перед необратимым действием запрашивать подтверждение.

## Память проекта

**Роль и проект.** Пользователь — продуктовый дизайнер. Это его рабочая среда, а не кодовая база продукта: здесь ведутся дизайн-задачи — ресёрч, информационная архитектура, экраны, прототипы.

**Договорённости.**
- Артефакты по задаче складывать в `projects/<имя-проекта>/`, не в корень.
- Цвета, типографику и компоненты брать из дизайн-системы. Значения руками не прибивать — ссылаться на токены и компоненты.
- Скиллы (`.claude/skills/`) и субагенты (`.claude/agents/`) заводятся под реальную повторяющуюся задачу, а не заранее.
- Ключи и токены в репозитории не хранить.

**Безопасность.** Перед необратимым действием — удаление файлов, публикация, отправка наружу, правка чужих макетов — спрашивать подтверждение.
