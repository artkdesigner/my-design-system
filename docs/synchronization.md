# Синхронизация с Figma

Повторяется при каждом изменении дизайн-системы.

1. Открыть файл дизайн-системы в десктопном Figma.
2. Plugins → Development → DS Variables Export → «Выгрузить переменные».
3. Положить скачанный `figma-export.json` в корень репозитория.
4. `npm run sync-tokens` — перегенерирует токены и покажет, что изменилось. Если
   в выгрузке появилась новая коллекция или режим, генератор упадёт с понятным
   сообщением — см. раздел «Новая коллекция режимов в Figma» ниже.
5. `npm run check-tokens` — числовая сверка: сравнивает значения токенов,
   уже лежащих в `ds/src/tokens/*.css`, со свежей генерацией прямо из
   `figma-export.json`. После шага 4 на той же выгрузке расхождений быть не
   должно; отчёт полезен, когда кто-то поправил файл токенов руками или забыл
   перегенерировать после новой выгрузки.
6. `npm test` — проверить, что компоненты не сломались.
7. `npm run storybook` — посмотреть глазами, сверить с Figma визуально
   (см. «Визуальная сверка» ниже).
8. Зафиксировать: `git add ds/src/tokens figma-export.json && git commit`.

## Визуальная сверка

Числовая сверка (`check-tokens`) ловит расхождения в значениях токенов, но не
видит вёрстку: отступы, радиусы, положение иконок — то, что зависит от разметки
компонента, а не от переменных. Это проверяется глазами, компонент за
компонентом:

1. Через Figma MCP (или просто глазами в Figma) открыть эталонный фрейм
   компонента со всеми вариантами и, если есть, отдельный фрейм с размерами.
2. Открыть тот же компонент в Storybook (`npm run storybook`) — историю с
   матрицей вариантов и историю с размерами.
3. Сравнить построчно: высоты, отступы по горизонтали, промежутки, радиусы,
   размеры иконок, цвета заливки и текста в каждом виде.

Каждое расхождение разбирается по одному правилу:

- **Значения** (цвета, размеры, отступы) — правда в Figma. Поправить в Figma,
  перевыгрузить, прогнать шаги 1–6 выше.
- **Поведение** (фокус, клавиатура, семантика, ARIA) — правда в коде.
  Токены здесь ни при чём, правки вносятся в компонент напрямую.

## Что скрипт не делает

Компоненты не трогаются никогда. Если в Figma изменилась структура
компонента — появился новый элемент, сдвинулась разметка — `sync-tokens`
об этом не узнает и не сообщит: он видит только переменные, не структуру
слоёв. Такие изменения переносятся в JSX/CSS компонента руками, и именно
для их отлова нужна визуальная сверка выше, а не только числовая.

## Новая коллекция режимов в Figma

`sync-tokens` и `check-tokens` упадут с сообщением о незнакомой коллекции
или режиме. Дописать её в `scripts/mode-selectors.json`: слой, порядок
(`order`, уникальный для каждой коллекции) и селектор для каждого режима —
см. комментарии в самом файле и в `scripts/lib/to-css.mjs` про то, почему
производные слои переизлучаются под несколькими селекторами.

## Коллизия имён

Если новая переменная Figma даёт то же имя CSS, что и уже существующая
(правило перевода имён схлопывает повторяющиеся слова пути — см.
`scripts/lib/naming.mjs`), `parseExport` упадёт с указанием обеих переменных.
Правильное решение — переименовать одну из них в Figma. Аварийный люк на
случай, когда переименовать нельзя прямо сейчас, — `scripts/name-overrides.json`
(описан в `scripts/name-overrides.md`).
