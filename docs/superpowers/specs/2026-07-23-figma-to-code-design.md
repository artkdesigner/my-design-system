# Перенос дизайн-системы из Figma в код

Дата: 2026-07-23
Статус: согласовано, готово к планированию работ

## Цель

Собрать из дизайн-системы в Figma работающий Storybook, который решает две задачи сразу:

1. **Передача разработчикам.** Витрина с токенами и компонентами плюс пакет, который подключается к продукту как зависимость.
2. **Сборка прототипов.** Агент собирает экраны из реальных компонентов дизайн-системы, а не из выдуманной разметки.

Обе задачи закрываются одним артефактом: Storybook — это одновременно документация для людей и рабочие компоненты для кода.

## Что обнаружено в источнике

### Токены цвета: 233 переменных, 72 уникальных значения

Четыре уровня, закодированные в именах переменных:

| Уровень | Токенов | Пример |
|---|---|---|
| `palette_*` — сырая палитра | 72 | `Blue/palette_blue_default` = `#2936cc` |
| `theme_*` — семантика | 71 | `Accent/theme_accent_default` |
| `state_*` / `element_*` | 70 | `BG/state_bg_accent` |
| `on-accent_*`, `message_*` | 20 | `Text/on-accent_text_primary` |

161 токен из 233 — ссылки на палитру. Значение `#2936cc` объявлено один раз и приходит в интерфейс через десять имён.

Уровень и режим — разные вещи, их легко перепутать. Уровень задаёт, на что токен ссылается (`state_*` смотрит на `theme_*`, тот на `palette_*`). Режим задаёт, каким будет значение на этом уровне при данном состоянии, теме или размере. Первое определяет структуру файлов CSS, второе — блоки внутри них.

### Коллекции режимов — основа архитектуры

| Коллекция | Режимы | Что переключает |
|---|---|---|
| ColorsTheme | темы | оформление целиком |
| ColorsState | Default, Hover, Pressed, Disabled | реакцию на действие |
| ComponentSize | L, M, S | плотность |

Состояния и размеры не заведены вариантами компонентов — они переключаются режимом коллекции. Это определяет всю архитектуру переноса (см. ниже).

### Типографика

- Шрифты: `Font family/Main` = Inter Tight, `Font family/Code` = IBM Plex Mono. Оба под SIL Open Font License.
- Начертания: Regular, Medium, Bold, Italic.
- Размеры: `body_m` 16, `body_l` 20; `heading_xs` 16, `heading_m` 24, `heading_l` 36, `heading_xl` 48.
- Межстрочные: 1.4 для body, 1.2 для heading.
- Составные стили (`Body M/Regular`, `Heading/XL` и т.д.) **сохраняют ссылки на переменные** в выдаче MCP, в отличие от цветов.

## Архитектура

### Ключевое решение: коллекция режимов = слой переопределения CSS

Каждая коллекция режимов Figma превращается в слой переопределения CSS-переменных, режим — в селектор. Различается только уровень применения.

```css
/* Слой 1 — палитра. Не меняется никогда. */
:root { --palette-blue-default: #2936cc; }

/* Слой 2 — ColorsTheme. Применяется на корне документа. */
:root               { --theme-accent-default: var(--palette-blue-default); }
[data-theme="dark"] { --theme-accent-default: var(--palette-blue-400); }

/* Слой 3 — ColorsState. Применяется на элементе. */
:root                     { --state-bg-accent: var(--theme-accent-default); }
.button:hover,
.button[data-state=hover] { --state-bg-accent: var(--theme-accent-600); }
.button:active,
.button[data-state=press] { --state-bg-accent: var(--theme-accent-700); }

/* Слой 4 — ComponentSize. Применяется на элементе или контейнере. */
[data-size="l"] { --button-height: 56px; --button-padding-hor: 24px; }
[data-size="m"] { --button-height: 40px; --button-padding-hor: 16px; }
[data-size="s"] { --button-height: 32px; --button-padding-hor: 12px; }

/* Компонент. О темах, состояниях и размерах не знает ничего. */
.button { height: var(--button-height); background: var(--state-bg-accent); }
```

Каждое состояние объявляется дважды: псевдоклассом (`:hover`) для настоящего взаимодействия и атрибутом (`[data-state=hover]`) для принудительного показа. Второе нужно Storybook — чтобы состояния можно было листать переключателем и видеть все сразу на одной странице, не наводя мышь. Пары обязаны идти вместе и задаваться из одного значения; расхождение между ними означало бы, что витрина показывает не то, что происходит в жизни.

Конкретные значения в примере (`--theme-accent-600` для наведения и подобные) взяты для иллюстрации механики. Настоящие приходят из выгрузки режимов ColorsState и в коде не придумываются.

Из этого следуют три свойства, ради которых схема и выбрана:

1. **Каждый слой ссылается только на предыдущий.** Компонент никогда не обращается к палитре напрямую. Смена акцентного цвета — одна правка в слое темы, расходится по всем 50 компонентам.
2. **Комбинации не нужно перечислять.** Слой состояний ссылается на слой темы, поэтому тёмная тема получает свои состояния автоматически. Четыре темы × четыре состояния дают 16 сочетаний без единой лишней строки.
3. **Скрипт синхронизации не знает семантики.** Обход общий: «для каждой коллекции, для каждого режима выдать блок». Появится пятая коллекция режимов — перенесётся без правки скрипта.

Размер работает и точечно, и оптом: `size="s"` на одной кнопке либо `data-size="s"` на панели — и всё внутри ужмётся. Это даёт наследование пользовательских свойств CSS, без дополнительного кода.

### Именование

Figma использует слэши (`BG/state_bg_accent`), в CSS они требуют экранирования. Правило перевода: группа отбрасывается (она уже продублирована в имени переменной), слэши и подчёркивания становятся дефисами.

```
BG/state_bg_accent               →  --state-bg-accent
Button/Button/Button_height      →  --button-height
Font size/Body/body_m            →  --font-size-body-m
```

Обратное соответствие хранится в `tokens.map.json` — чтобы при следующей синхронизации понимать, что чему отвечает, и показывать разницу.

### Storybook

Три вещи, которые делают из набора компонентов витрину:

- **Раздел Foundations генерируется из токенов.** Страницы палитры, типографики и шкал собираются из тех же файлов, что и компоненты, поэтому физически не могут разойтись с кодом.
- **Переключатели темы, состояния и размера в панели.** Вешают `data-theme`, `data-state` и `data-size` на корень предпросмотра — тот же жест, что переключение режима в Figma. Состояния можно смотреть, не наводя мышь.
- **Статическая сборка для передачи.** Собирается в папку с готовым сайтом: кладётся на любой хостинг или отдаётся архивом, Node для просмотра не нужен.

## Принципы переноса компонентов

Компоненты пишутся вручную, не генерируются. Хороший компонент — это не только внешний вид: это семантика, доступность, состояния и понятный API пропсов, и ничего из этого в макете нет.

**Варианты Figma не переносятся один в один.** В Figma 24 варианта кнопки, потому что у неё нет условной вёрстки. В React часть из них выводится:

```tsx
type ButtonProps = {
  view?: 'accent' | 'primary' | 'secondary'
  size?: 'l' | 'm' | 's'          // по умолчанию 'l'
  ghost?: boolean
  danger?: boolean
  iconLeft?: ReactNode
  iconRight?: ReactNode
  children?: ReactNode
} & ButtonHTMLAttributes<HTMLButtonElement>
```

- **`iconOnly` пропа нет** — состояние выводится: нет текста, есть иконка. Проп создавал бы противоречивое состояние (включён `iconOnly`, но передан текст). Типизация при этом требует `aria-label` у кнопки без текста, иначе для скринридера она немая.
- **`leftAddon` / `rightAddon` из булевых стали слотами.** В Figma флаг лишь освобождает место, иконку подменяют вручную; в коде передаётся сама иконка, её наличие и есть флаг.
- **24 варианта → 12 сочетаний** (`view × ghost × danger`), остальное выводится. В Storybook при этом показывается полная матрица для сверки с макетом.

Вёрстка идёт только на токенах, без чисел в коде. Фокус берётся на `--element-border-focus` и вешается на `:focus-visible` — кольцо появляется при работе с клавиатуры, но не при щелчке мышью.

## Синхронизация с Figma

### Источник значений — плагин, не генератор кода

Тариф Pro, REST API переменных недоступен (только Enterprise). Пишем собственный плагин Figma: в режиме разработки он работает на любом тарифе, публиковать не нужно. Внутри Figma доступен API переменных, отдающий то, чего не отдаёт MCP: коллекции, все режимы и ссылки между токенами в явном виде.

Свой плагин выбран вместо готового из Community, чтобы формат выгрузки был наш и не зависел от чужих изменений.

**Сгенерированный Figma код как источник значений не используется.** Зафиксировано два искажения на одном лишь Button:

- `min-width` отдан числом (`120px`), хотя переменная существует и меняется по режимам;
- `label_font-size` отдан как `16px` для всех трёх размеров, тогда как фактические значения 16 / 14 / 12.

Генератор используется только как визуальный эталон разметки.

### Порядок

1. Запустить плагин в Figma — он кладёт `figma-export.json`.
2. `npm run sync-tokens` — перегенерирует токены и печатает разницу.
3. Просмотреть разницу, прогнать Storybook, зафиксировать.

Компоненты скрипт не трогает никогда. Если в Figma изменилась структура компонента — только сообщает. Иначе перестановка слоя в макете затрёт написанную вручную доступность.

## Проверка соответствия

Два независимых контроля:

**Числовой.** Скрипт перечитывает переменные из Figma и сравнивает со значениями в коде. Выдаёт список расхождений вида «`--theme-accent-default` в Figma `#2936cc`, в коде `#2936ff`». Дёшево, точно, ловит дрейф значений.

**Визуальный.** Снимок компонента из Figma и снимок из Storybook рядом, сравнение глазами с перечислением различий. Ловит то, что числами не поймать: отступы, выравнивание, потерянные иконки.

Пиксельное сличение автоматом не делается: рендеринг шрифтов и сглаживание в браузере и в Figma отличаются всегда, такой тест даёт ложные срабатывания и его быстро отключают.

**Правило при расхождении:** Figma — источник правды для значений (цвета, размеры, отступы). Код — источник правды для поведения (фокус, клавиатура, семантика, ARIA). Области не пересекаются.

## Порядок работ

1. **Плагин выгрузки переменных** — вытащить коллекции, режимы и ссылки.
2. **Скрипт `sync-tokens`** — сгенерировать четыре слоя CSS плюс типы.
3. **Каркас пакета и Storybook** — сборка, разделы, переключатели темы/состояния/размера.
4. **Foundations** — страницы палитры, типографики и шкал из токенов.
5. **Button** — эталонный компонент со всеми режимами и полной матрицей вариантов.
6. **Сверка** — числовая и визуальная, до полного совпадения.
7. **Остальные компоненты** — пачками по 5–7 родственных.

Шаги 1–6 проверяют весь конвейер на одном компоненте. Только после этого имеет смысл масштабировать: ошибка в фундаменте, найденная на сороковом компоненте, означает переделку всех сорока.

## Отдельные вопросы

**Шрифты.** Inter Tight и IBM Plex Mono кладутся в пакет файлами. Без этого у разработчика без установленных шрифтов Storybook отрисуется системным и вся типографика поедет.

**Иконки.** Figma отдаёт их временными ссылками на локальный сервер, живущими до закрытия приложения. Нужен отдельный проход: выгрузить SVG в репозиторий и собрать в компонент. Кнопка к этому готова — принимает любую иконку как `ReactNode`, поэтому перенос иконок можно делать в любой момент.

## Что осознанно не делаем

- **Не генерируем компоненты автоматически.** Выдача Figma — разметка с абсолютным позиционированием и служебными атрибутами; как библиотека для передачи разработчикам она непригодна.
- **Не переносим все 50 компонентов сразу.** Сначала конвейер на одном.
- **Не настраиваем Code Connect** на этом этапе. Имеет смысл после переноса, когда есть к чему привязывать.
- **Не подключаем Tailwind.** Токены ложатся на пользовательские свойства CSS напрямую; Tailwind добавил бы слой преобразования без выигрыша.

## Открытые вопросы

1. **Состав ColorsTheme** — сколько тем и как называются режимы. Выяснится при первой выгрузке плагином, на архитектуру не влияет.
2. **Полный список токенов Padding и Radius.** Через MCP виден частично (`Padding/0, 4, 8, 24, 48`, `Radius/4, 24`), потому что инструмент отдаёт только задействованные на странице. Полный список даст выгрузка.
3. **Git.** Репозиторий не инициализирован. Для пакета, который передаётся разработчикам, нужен — но это решение пользователя.
